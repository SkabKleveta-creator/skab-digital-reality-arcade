Warehouse-in-the-Loop

A tabletop diagnostic for validated warehouse flow under human processing limits.

This v0.2.2 deck explains the Dock-to-Stock Collapse module: a safe-to-fail exercise for the warehouse failure mode dashboards miss. It tests whether a team can preserve flow without sacrificing accuracy, safety, evidence, or human comprehension.

So What

Not a cute warehouse game.

What it reveals

Where process, data, people, and priority disagree before the real warehouse pays for it.

What it trains

A team slows just enough to make the next action executable, not merely fast.

What it proves

Validated flow beats false throughput. A documented hold can be better than a dirty ship.

What It Is / Is Not

Tabletop diagnostic, not digital simulator.

This is

  • A tabletop diagnostic module
  • A facilitator-supported hidden-state exercise
  • A way to test validation behavior
  • A structured AAR on warehouse execution

This is not

  • A digital warehouse simulator
  • A throughput race
  • A campaign or lore expansion
  • A replacement for human judgment

Doctrine

Humans need time and context before they can execute the next right action.

Scenario

Dock-to-Stock Collapse

Opening condition

A mission-critical inbound surge hits. The system says the queue is fine. The floor disagrees.

Visible symptoms

Receiving backlog, Pick Face shortage, and Pack / Ship cutoff pressure.

Hidden truth

Ghost inventory, unofficial staging storage, and an old process still being followed.

Mechanic

Processing becomes useful.

1. Floor ReadbackWhat changed? What is unknown? What is at risk?
2. Processing PauseName an assumption, risk, or proof requirement.
3. InsightEarn foresight, not a stat bonus.
4. CommitWe are doing X because Y. We will know it worked when Z.
5. ValidateProve the gain or expose the false green.

The Pause is not a delay. It is how the team earns enough foresight to avoid rushing into the wrong fix.

Decision Economy

Five actions, hard boundaries.

ObserveUnknown -> evidence
StabilizeThreat -> controlled
RouteConstraint -> flow
ExceptionProtect or Push, declared aloud
ValidateClaim -> proof

AI Steward

Memory, not decision replacement.

The AI / facilitator preserves hidden state and pressure. Humans still choose, commit, validate, and own the judgment.

Ghost Inventory

WMS says 40 units. Physical count says 6. The missing units never posted after a failed batch upload.

Staging as Storage

Receiving backlog includes old overflow, not just inbound freight.

Old Process

A new rule went by email. Day shift half-adopted it. Night shift never saw it.

Run Format

How to run it without turning it into a meeting.

0-5: Setup

Board, roles, tracks, tokens, and Round 1 readback.

5-30: Five rounds

Readback -> Pause -> Action -> Reaction -> Record / Validate.

30-40: Decision + AAR

Ship with evidence, hold with documented risk, or ship without proof. Then name the real constraint.

Next Move

Prove the floor first.

Do not add content before first run

No digital version yet. No campaign layer yet. No new tracks, zones, cards, or mechanics yet.

Fix only what the table proves

Confusing timing, unclear action resolution, Insight abuse/uselessness, facilitator burden, Ground Truth Brief gaps, or a Pause that feels fake.

Final BLUF

Print it. Run it. Let the AAR tell us what is real.
